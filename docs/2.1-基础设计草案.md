# 人事管理 2.1：基于现有仓库的基础设计草案

**状态：**设计草案；阶段 1 的增量 Prisma schema 和迁移 SQL 已在本地生成，尚未应用到数据库或启用生产人事接口。  
**依据：**[开发规格](人事管理2.1开发规格.md)、[仓库审计](2.1-仓库审计与差异清单.md)及 2026-10-13 用户补充确认。

## 1. 与 1.0 的隔离边界

- `User` 保留为登录与现有经营权限账号；POS 每日同步仍按 1.0 运行。员工人事档案应有独立主键和生命周期，可选关联一个 `User`，不得用 POS 账号停用直接认定离职。
- `StoreDailyInput.laborHours` 是门店日汇总，不从新员工工时表静默覆盖。1.0 日报、POS 映射、菜品与入客数规则均保持原状。
- 新增人事 API 置于独立模块和路由。现有 `UserRole` 三个枚举不直接承担人事审批；避免 POS 同步覆盖后台配置的人事角色。

## 2. 后台可配置的人事角色

用户已确认“角色由后台设定”。建议增加独立的人事角色、权限代码、用户角色授予及作用范围，范围至少能表示全组织、区域或门店；角色配置由具有明确配置权限的账号维护，并记录每次变更审计。转店审批的原店、新店、人事是**流程节点**，实际审批人须按当时的后台配置和门店作用域解析并固化在申请上，避免配置变化导致在途审批人漂移。

尚待确认：后台是否允许修改权限代码到角色的映射、谁可维护配置、调薪与月审各节点需要哪些角色、是否允许代理或同一人兼多个节点、本人申请的回避规则。因此这里只确定设计方向，不给数据库枚举或迁移定稿。

## 3. 可先固定的业务内核

### 工时

`packages/hr-engine` 接收**已经归属同一员工、同一业务日且确认有效**的原始分钟段，先求和，再按 30 分钟向下折算；同时返回原始、统计和舍弃分钟。规则号为 `DAILY_30_MIN_FLOOR_V1`。入参不处理跨午夜和跨店分摊，返回值不代表工资支付金额。原始班段、休息和更正版本将在数据库设计确认后另外保存。

现已补充绝对时间分钟差与休息扣除的纯函数，可处理跨午夜的实际时长；调用方仍须把门店本地时间明确转换为绝对时间，并按待确认规则归属业务日。员工主门店任职段另有纯冲突检查，采用左闭右开的生效日期区间，可识别重叠和重复主归属；它不决定转店生效日，也不处理兼岗。

### 转店

用户确认的顺序为原店 → 新店 → 人事，串行审批；任一方拒绝则不执行。`packages/hr-engine` 的纯流程函数只验证顺序与终止条件；三方通过后进入“已批准、待生效”，不自动改变门店归属。生效日期、撤回、超时、兼岗和跨店同日规则仍待确认。

## 4. 拟建实体及事务边界

以下是逻辑实体，**不是已经创建的表**：

1. 员工档案、任职区间、账号关联：历史不覆盖；同一时点主门店归属不得冲突。POS 员工编码与手机号仅作匹配线索，冲突要人工处理。
2. 人事角色、权限、作用范围及授予记录：审批任务保存当时解析出的人员及配置版本；服务端同时检查账号、角色、门店、有效日期和任务当前节点。

阶段 1 的实体与约束详见[数据库设计与迁移检查](2.1-阶段1数据库设计与迁移检查.md)。角色配置写接口、审批任务与权限代码尚待业务规则确认，当前表结构只提供独立存储基础。
3. 转店申请、三个审批决定和生效记录：一个申请一次生效；审批与生效使用事务和版本号防并发重复；历史班次和工时维持发生门店。
4. 排班及发布版本、逐人通知投递：消息幂等键采用班次 ID、版本、员工、消息类型；一人失败不撤销其他人排班。发送前核验最新版本和微信授权。
5. 实际出勤原始班段、确认与更正版本、派生日统计：原始分钟永存，更正追加版本；30 分钟统计可按规则版本重算。
6. 调薪版本、月度审核与导出快照：只在审批与计算规则明确后建表。月审批准后冻结输入与规则版本；重开形成新版本而不改旧 Excel。
7. 身份与银行卡资料：先确定必填字段、处理依据、访问角色和保存期限，再设计加密、文件存储、审计及迁移。当前仅预留 `apps/api/src/hr/ocr-provider.ts`，没有采集或上传接口。

## 5. 实施顺序和兼容迁移

1. 核对尚缺的业务决定、角色维护边界及生产备份恢复；冻结可追溯的 1.0 源码和镜像清单。
2. 先设计员工身份与人事权限，再审查 Prisma 增量迁移。只新增 2.1 数据，不改 1.0 表结构和现有接口行为；迁移前验证数据库备份可恢复。
3. 分别交付员工/任职、转店、排班通知、工时确认、调薪月审；每阶段先验证服务端授权与状态机，再接前端。
4. 敏感资料采集、微信排班发送、正式月审导出分别经过规格中的上线闸口。OCR 服务商后续通过适配器接入。

## 6. 需用户补充的决定

- 入职证件及银行卡的逐项必填字段、图片要求、银行卡核验与本人确认方式。
- 后台角色配置的管理员、权限范围、调薪与月审审批节点及回避规则。
- 转店三方批准后的生效方式、是否允许兼岗、撤回和超时规则。
- 跨午夜班次的业务日归属、休息扣除和跨店同日工时的统计范围。
- 微信排班通知的可用模板、授权条件与无授权时补救方式。
