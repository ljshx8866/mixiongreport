# 系统告警收件箱

## 监控范围

- API 请求抛出 HTTP 500 及以上异常时，立即写入告警；相同接口和错误内容会合并，累计发生次数，并在再次发生时重新标为未读。
- 后台每 5 分钟扫描一次 POS 同步失败日志。相同门店、同步接口和错误内容合并成一条告警；原同步日志仍保留，可继续从日报同步日志查看。
- 每日 POS 门店、分类、菜品或用户主数据同步失败也会直接写入告警箱，并按错误内容合并。
- 入箱前会隐藏手机号、证件号、银行卡号和常见密钥字段，不记录请求正文或请求头。
- 初次启用只扫描最近 3 天的 POS 失败日志；上线前更早的历史日志不会作为新告警导入。

## 查看和处理

管理员进入后台“系统设置 → 系统告警”。页面默认显示未读告警，支持按未读、已读、已解决和全部筛选；可以标记已读、已解决，也可重新打开。

每条告警显示来源、接口、HTTP 状态、错误次数、首次和最近发生时间，以及根据错误内容匹配的排查建议。具体失败信息只对管理员接口开放。

## 自动诊断与修复边界

告警分类和建议是规则匹配，用来缩小排查方向，不代表系统已经证明根因。日报提交后的 POS 同步仍沿用现有安全重试逻辑；监控器不重复提交日报、不改经营数据、不修改权限或员工资料，也不自动改代码、重启服务或发布版本。

API 完全停止、Docker 主机故障或数据库不可连接时，API 自身无法把告警写进数据库收件箱。若需要覆盖这类整机故障，需另外接入主机外部的可用性监控和告警通道。

## 数据库与任务

- 表：`system_alerts`
- 同步日志处理标记：`api_sync_logs.alerted_at`
- 同步失败扫描周期：每 5 分钟
- 默认保留告警记录；管理员可将处理完成的记录标为已解决。
