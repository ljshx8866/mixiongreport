## 已实现并通过本地测试

- 人事角色、门店/区域/全局作用域授权及可配置审批链；不继承经营日报权限。
- 员工非敏感草稿、原店→新店→人事串行转店审批、指定日期追溯生效及历史任职段。
- 次日排班草稿与发布版本；排班通知队列、逐人绑定检查、微信回执、失败原因与有限手动重试已实现。模板/授权未就绪时记为 `UNAVAILABLE`，生产发送开关默认关闭。
- 已确认工时原始记录、每个班次独立按 30 分钟向下统计、更正审批及月审失效处理。跨夜拆分能力保留，当前业务不排跨夜班次。
- 自然月审核、异常阻断、审批快照和 Excel 导出；导出只接受有效已批准快照，校验哈希并记录文件哈希。
- 后台人事角色、审批链、员工草稿、月度工时审核入口，均受功能开关限制；员工草稿和月审菜单按当前人事授权显示可访问门店，不继承经营日报的管理员/门店权限。月审提交、审批、导出权限分别控制；仅有审批权限的人也能查看待审月份。
- 阿里云身份证 OCR 官方 SDK 的二进制请求、响应适配器与输入限制；新增受权限保护的图片识别预览入口，只接受 JPEG/PNG，返回结构化建议供人工确认，不保存原图。服务端专用密钥工厂已完成，但未配置生产密钥。身份证和银行卡的结构化草稿已接入独立的追加版本表：只存加密内容和掩码，身份证指纹防止当前员工重复绑定，审计仅记录版本号。HTTP 入口要求人事专属权限、`HR_FEATURES_ENABLED` 和独立的 `HR_SENSITIVE_INTAKE_ENABLED`；OCR 还要求 `HR_OCR_ENABLED`。三个开关在 Compose 均为关闭。
- 入职申请首版后端流程：门店现场核验身份证原件和银行卡后提交，锁定两类敏感草稿版本，走后台配置的审批链；人事查看脱敏结果。批准后按申请日期在同一事务中建立任职记录及已核准银行卡版本，只引用加密草稿，不复制明文；未来日期等待生效，拒绝不生效，资料版本变化则进入失败状态。后台已有入职资料和审批入口。`HR_ONBOARDING_ENABLED` 默认关闭，该流程及新增迁移仍待隔离 MySQL 验证。
- 新增后台入职审核、离职和时薪变更页面。离职、时薪变更有独立审批与有效期逻辑；基础应发工资按每日有效时薪和逐班次统计工时计算，每日四舍五入到分后汇总。对应开关默认关闭。
- 小程序本地增加人事入口、本人排班、本人工时、门店排班、工时确认、更正申请/审批和转店页面，尚未上传线上版本。本人排班只通过已绑定账号查询本人的已发布班次；更正仍受后台审批链与门店权限控制。
- API 镜像启动已取消自动迁移；迁移改为发布时显式执行。Compose 明确将 `HR_FEATURES_ENABLED` 固定为 `false`，上线审批前不会意外开放人事 API。

验证：2026-10-15 本地小程序微信平台构建、API 构建、后台构建均通过；18 项人事计算测试和 76 项 API 测试通过。此前因自动审批额度不足而未执行的小程序构建已重新执行成功。Prisma schema validate 通过，入职、离职、时薪四张新增表的目标 DDL 与迁移静态一致，见[迁移静态核对](2.1-迁移静态核对.md)；新加的银行卡生效版本迁移尚待隔离 MySQL 实际验证。以上不等于真机、真实微信订阅消息、真实阿里云 OCR 或隔离 MySQL 全迁移验收；本机无 Docker/MySQL，当前环境 SSH 不可用。

## 已确认口径

- 转店：原店、新店、人事串行审批；任一拒绝不执行；全部通过后按申请日期自动生效，晚批追溯。
- 审批角色/顺序在后台配置，不预设调薪、工时更正、月审审批人。
- 每个班次独立按 30 分钟向下取整，不足 30 分钟不计，原始分钟保留；当前不排跨夜班次。
- 时薪基础工资按每日统计工时乘当日有效时薪，每日金额四舍五入到分，再求月合计。
- 身份证 OCR 服务商选阿里云；入职收姓名、身份证识别主要信息、银行卡信息，预留扩展字段。
- 身份证原件与银行卡资料由门店现场核验；人事审批只看脱敏结果。
